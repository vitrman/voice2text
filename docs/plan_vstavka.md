# План: почему текст не вставляется автоматически

Статус: отложено, ждёт диагностики. Текст в буфер попадает (ручной Ctrl+V работает),
автоматическая вставка в чужое окно — нет.

## Гипотезы

1. **Фокус не там.** `SetForegroundWindow` из фонового процесса игнорируется,
   проверка проходит по своему дескриптору, ввод уходит в окно приложения.
2. **Синтетический ввод отбрасывается.** Часть контролов (Qt/Java/отдельные поля 1С)
   игнорирует клавиши с `LLKHF_INJECTED`, при этом `SendInput` возвращает успех.
3. **Модификаторы зажаты.** Инжект превращается в Ctrl+Shift+V, который приложения
   игнорируют.
4. **Цель — не контрол.** Верхнее окно верное, фокус внутри на панели/вкладке.
5. **Нет скан-кодов.** `wScan=0`; приложения на Raw Input такие события не принимают.
6. **Наш клавиатурный хук** мешает доставке (маловероятно).

## Диагностика (первый шаг)

Писать в лог: заголовок цели, `GetForegroundWindow` до и через 150 мс после,
`GetGUIThreadInfo.hwndFocus` и класс контрола, состояние Ctrl/Shift/Alt,
результат `SendInput`. Отделяет H1 от H2/H5.

## Решения

- **A. Адресная вставка в контрол**: `GetGUIThreadInfo` → `hwndFocus`,
  `WM_PASTE` для Edit, `EM_REPLACESEL` для RichEdit; иначе SendInput.
- **B. Усилить SendInput**: `MapVirtualKey` + скан-коды, отпускание модификаторов,
  пауза 150–250 мс, повтор с проверкой фокуса.
- **C. UI Automation**: `ValuePattern.SetValue` / `TextPattern` — Chromium, Notepad,
  WinForms/WPF; 1С частично.
- **D. Fallback**: оставить текст в буфере и показывать тост «Ctrl+V».

Порядок: диагностика → A + B → C при необходимости.
