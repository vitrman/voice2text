# Изменения

Формат версии: `MAJOR.МИНОР.ПАТЧ.1` (как у больших конфигураций, четвёртое число всегда 1).

## 0.8.6.1
- Режим «удерживать» работает с любым хоткеем: остановка по отпусканию клавиш теперь
  опрашивает фактическую комбинацию, а не зашитые Ctrl+Alt+Space. Раньше с `alt+f9`
  запись шла до лимита, и второе нажатие уже не останавливало её. Хук клавиатуры больше
  не участвует в остановке — он не видит нажатий в окнах, запущенных от администратора.
- Состояние хоткеев вынесено в `hotkeys.py` (комбинации, коды, фактически
  зарегистрированный вариант): раньше это были четыре глобальных словаря в `app.py`,
  которые надо было править согласованно в трёх местах.
- Занятая комбинация больше не скрывается: поле получает оранжевую рамку, подсказка
  говорит, что реально работает, а при записи новой комбинации занятость проверяется
  сразу. Раз в минуту приложение пробует вернуть желаемую комбинацию.
- Обновление больше не зависит от кодировки консоли: установщику передаётся
  `/WAITPID=<pid>`, он сам ждёт выхода приложения. Пакетный файл с путями внутри
  (кириллица в `%TEMP%` и `%LOCALAPPDATA%` ломала `cmd`) больше не создаётся.
- Удаление программы переведено на `Voice2Text.exe --uninstall`: ярлык «Голосовой ввод»
  удаляется WinAPI, а не `del` из командного файла, где русское имя не читалось.
- Скачанное обновление проверяется по sha256 (из `digest` релиза или файла `*.sha256`)
  и по целостности zip до запуска установщика.
- Кэш обновлений в `%TEMP%` убирается при старте: архивы и распаковки не новее
  установленной версии удаляются, остатки `*.old` от неудачных установок тоже.
- Установщик после распаковки удаляет файлы, которых нет в новой версии: старые
  библиотеки больше не остаются в `_internal` и не подхватываются вместо новых.
- Микрофон хранится по имени и host API, а не по номеру: подключение USB-гарнитуры
  больше не уводит запись на другое устройство. Список устройств обновляется при
  открытии, пропавший микрофон даёт сообщение в статусе.
- Настройки сохраняются атомарно (временный файл + `os.replace`) и с `config.bak`:
  обрыв питания не оставляет пустой `config.json`, а повреждённый файл
  восстанавливается из копии с записью в журнал.
- Загрузка модели защищена блокировкой, смена модели применяется в простое и освобождает
  старый чекпойнт: больше нет двойной загрузки 428 МБ и двух моделей в памяти.
- VAD: шумовая полка считается по минимуму первых блоков, калибровочные 300 мс идут в
  запись (не отрезается начало фразы), а если уровень был выше шума — запись уходит в
  распознавание вместо ложного «Речь не обнаружена».
- Второй запуск поднимает окно первого через именованное событие, а не показывает
  сообщение «ищите иконку в трее».
- Из списка моделей убраны не-e2e `v3_rnnt`/`v3_ctc` (сплошной текст без пунктуации и
  регистра выглядел как «хуже распознаёт»); старые значения в конфиге мигрируют на
  `v3_e2e_rnnt`, остались две e2e-модели с подписями «точнее» и «быстрее».

## 0.8.5.1
- Скачанное обновление больше не теряется и не качается заново: архив лежит в
  `%TEMP%\voice2text-update` и переиспользуется, если размер совпадает с релизом
  (`update.cached`). Вопрос перед установкой теперь различает «скачать 243 МБ» и
  «уже скачано, установить».
- Окно обновления с прогрессом и кнопкой «Отмена»: скачивание можно прервать,
  недокачанный `.part` удаляется. Повторный запуск проверки во время скачивания
  игнорируется — двух параллельных загрузок одной версии больше не бывает.
- Установка обновления: вместо удаления папки программы файлы кладутся поверх
  (exe на время распаковки переименовывается в `.old`), поэтому занятые файлы не ломают
  установку, а при сбое exe возвращается на место. Приложение перезапускается даже при
  ошибке установки — раньше оно просто закрывалось и не открывалось.
- Скрипт-помощник `%TEMP%\voice2text-update\apply-update.cmd` ждёт завершения процесса по PID,
  пишет лог установки в `install.log` и только потом запускает новую версию.

## 0.8.4.1
- `push.cmd` — выкладка кода и тегов на GitHub (`push.cmd pull` / `push.cmd force` для
  конфликтующих историй).
- `release_github.cmd` + `tools/publish_release.ps1` — публикация релиза с архивом установщика:
  через GitHub CLI, если он авторизован, иначе по токену через REST API; `-DryRun` показывает
  версию, тег и путь к архиву без обращения к сети. Заметки релиза берутся из `CHANGELOG.md`.
- Исправлена ошибка `not enough values to unpack (expected 3, got 2)` в `model_fetch._download`:
  из-за неё предварительная загрузка модели падала, и GigaAM качал чекпойнт сам —
  на 449 МБ это 12 минут без прогресса. Теперь качает наш параллельный загрузчик с докачкой.
- Причина сбоя подготовки модели пишется в журнал с полной трассировкой.
- Проверка обновлений: 404 (на GitHub ещё нет релизов) и 403 (лимит запросов) больше
  не валят трассировку в журнал, а показываются коротким сообщением.
- Автопроверка обновлений — не чаще раза в 12 часов (`last_update_check` в конфиге),
  чтобы не дёргать API при каждом запуске.

## 0.8.0.1
- Исправлена ошибка на чужих машинах `FileNotFoundError [WinError 2]` при распознавании:
  GigaAM читал WAV через внешний `ffmpeg` из PATH. Загрузчик аудио подменён на
  `soundfile`/`wave` с ресемплингом через scipy (`asr_engine._patch_audio_loader`) —
  ffmpeg больше не нужен ни в exe, ни при запуске из исходников.
- Журнал стал пригодным для диагностики по чужому логу: в нём дата и время, версия,
  `frozen`, пути ROOT/DATA, версия Python и Windows, наличие ffmpeg, признак прав
  администратора, свободное место, каталог модели и список микрофонов.
  Ошибки пишутся с полной трассировкой (`trace_exc`), файл ротируется после 2 МБ.
- Меню «Справка»: «Проверить обновления…», «Открыть журнал», «Открыть папку данных».
- Обновление из GitHub Releases: `update.py` читает последний релиз через публичный API,
  сравнивает версии, скачивает `*-installer.zip`, ставит его в тихом режиме поверх текущей
  папки и перезапускает приложение. Проверка при старте (через 15 с, если `check_updates`)
  и вручную из меню; пользовательские данные в `%LOCALAPPDATA%` не затрагиваются.
- Новые ключи конфигурации: `check_updates`, `github_repo`.

## 0.4.1.1
- Вставка в чужое окно. «Своё» окно определялось сравнением HWND, а `wm_frame()` отдаёт
  другую рамку, чем `GetForegroundWindow()`, поэтому проверка не срабатывала и текст
  вставлялся в само приложение. Теперь окно считается своим по PID процесса
  (`_is_own`), а не по совпадению HWND.
- Цель вставки: если в момент старта записи фокус в нашем окне, берётся последнее чужое
  окно (`last_external`), а не пустая/своя цель.
- Перед `Ctrl+V` проверяется, что фокус действительно у цели и она не наша; иначе
  текст остаётся в буфере, а не уходит «в никуда». В лог пишется foreground, target и признак «своё».

## 0.4.0.1
- Кнопка «Стоп» на форме теперь реально останавливает запись: раньше обработчик
  останавливал только режим рации, а кнопка, запустившая запись, ничего не делала.
- Надпись кнопки «Записать/Стоп», заголовок трея и уведомление берут фактический хоткей,
  а не зашитый в код `Ctrl+Alt+Space` — из-за этого казалось, что хоткей не переопределился.
- Хоткей — только комбинация «Ctrl/Shift/Alt + клавиша»: одиночные клавиши и Win отклоняются
  при записи, с подсказкой в диалоге настроек.
- Старые одиночные и модификаторные хоткеи (`space`, `ctrl+alt`, `alt+win`) при загрузке
  конфигурации заменяются на `ctrl+shift+space`.
- Сохранение настроек больше не прерывается вопросом про Alt — Alt просто разрешён.
- Удалён перехват «комбинаций из одних модификаторов» хуком: он путался между
  `ctrl+alt`, `alt+win` и порядком нажатия. Все хоткеи снова идут через `RegisterHotKey`.
